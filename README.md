# 静读 Android App

手机端 Android 版本的静读阅读模式。应用使用 WebView 在本地加载网页，再通过页面内 JavaScript 提取正文、目录章节链接和目录分页，阅读内容由原生 Compose 界面渲染。

## 功能

- 输入小说网页地址并打开。
- 首页、书架、搜索、设置拆成四个独立页面，通过底部导航切换；启动后停在首页，不会自动打开上次的书（从系统分享链接进入时才会直接进阅读）。
- 书架条目左滑露出操作：重命名、复制网址、分享网址、移出书架；条目本身直接显示最近阅读的章节网址。
- 搜索页支持输入书名并限定站点（默认微妙看书），搜索在隐藏 WebView 里完成（必应优先、百度兜底），结果可直接「打开阅读」或「保存到书架」。
- 阅读页中央菜单支持将当前书籍加入书架，书架会记录最近阅读章节；移除书籍只在书架页操作。
- 自动识别正文和目录页。
- 目录页完整渲染章节链接，不限制 500 章。
- 识别 `上一页`、`下一页`、`101-200`、`第 2 页` 等目录分页链接，以及用 `<select>` 下拉切换页码的目录，并在后台自动加载、合并所有可发现的目录页。
- 目录容器同时识别 `#list`、`.listmain`、`.section-box`、`.section-list` 等常见结构；同一页同时出现“最新章节”和“正文”列表时优先采用完整正文目录。目录翻页会轻微节流，降低被站点反爬拦截的概率。
- 手机端支持上下滚动和左右分页两种翻页方式，并记住选择。
- 阅读窗口固定保持当前章、上一章和下一章三章数据：当前章由活动 WebView 读取，前后章由两路独立 WebView 并行预加载，解析后存入本地内存缓存；阅读切章命中缓存时直接衔接。打开一章时会立刻用本地缓存把本章（含续页）、上一章、下一章组装进窗口，不需要等后台下载完成；后台只额外预热下一章，读到下一章后再补一章（同一章不会重复下载），且后台读取不会打断前台滚动或翻页。
- 上下阅读会把已缓存的上一章、本章和下一章接在同一条滚动内容中，向上或向下滚入相邻章节时连续衔接；停在章节首尾不会自动跳转，只有继续滚动或边界手势才会进入相邻章节。
- 从章节开头左翻会落到上一章末页，从章节末尾右翻会落到下一章首屏。
- 上下/左右阅读模式切换时会保留当前正文偏移，不再因残留的章节起始定位标记跳回本章开头。
- 横向模式下系统状态栏和导航栏背景会跟随当前象牙白、纸张灰或夜间墨色设置，正文与页码仍限制在安全区域内。
- 阅读页中央五分之一宽度区域用于呼出菜单，左右区域用于翻页；横向模式支持点击左侧上一页、右侧下一页，或通过短滑动立即翻页；设置中可改为左右两侧都进入下一页。
- 横向阅读在内存里组装一条连续页序列：上一章末页、本章全部页、下一章全部页。章节只是序列里的接缝，因此点击右侧翻页、点击左侧回退、滑动翻页在章节边界与章节内部行为完全一致；回到上一章末页也不再需要重新打开上一章。相邻章在后台就绪后会立即并入序列，不需要重新打开本章。
- 对分成多个网页的章节自动合并 `上一页`/`下一页` 正文；即使站点在手机版把分页链接隐藏起来（例如微妙看书），也会根据正文里的「本章未完，请点击下一页」提示按常见续页命名（`_2.html` 等）取回后一页，避免只读到半章。章节标题去除分页和站点后缀；纵向和横向阅读都显示完整标题，横向首页会按标题实际高度重新分页；分页截点落在完整视觉行末，正文底部保留 1dp 安全间距；只有靠近页面边界的段落换行才会优先保留，较长段落会在页面中连续分页，避免前页留下大段空白；末尾连续的短页、孤立标点或引号会合并后重新平衡，必要时减少页数，避免生成异常留白页。
- 分页链或下一章缓存尚未完整时不会提前提交章节切换，待正文合并完成后再继续阅读。章节缓存不会被「后到的单页解析结果」覆盖成半章：已合并完整正文的章节在再次打开、切换前后章、重启应用后仍然是完整正文。
- 阅读器会过滤正文中的导航、强制阅读提示和浏览器错误页；前后章预读取和原生 HTML 兜底会沿用当前 WebView 的站点 Cookie 与 Referer，遇到普通预读取失败时自动转到活动 WebView 继续加载；遇到 Cloudflare 安全验证时保留可交互的 WebView，验证通过后继续提取章节。
- 网页读取失败时错误页会保留最近 150 条诊断事件，可一键复制或通过 Android 分享面板发送；日志包含应用版本、设备 API、加载阶段、网页地址、请求 token、WebView/HTTP 错误、站外跳转拦截和重试状态，不包含正文内容。
- 当前章节正文和阅读位置会在切换页面、离开阅读页及进程结束前保存；上下模式额外保存可见段落和像素滚动偏移，重新打开书架或最近阅读可继续原位置；已合并的目录独立保存，应用重启后可继续目录加载。
- 恢复已保存的章节时会立即重新准备前后章节缓存，避免首次读到章节边界时退回活动网页加载。
- 章节页只提供「下一页」而不提供「下一章」的站点（例如微妙看书）会以已加载目录推断相邻章节，读完一页即可继续下一章；目录在后台自动补齐，不需要手动打开目录抽屉。目录条目与实际章节地址的文件后缀（`.html`）、正文续页后缀（`_2`）会一起归一化匹配，书页本身不会被当成一章，因此目录加载完成后「上一章」「下一章」即可用。
- 已保存的完整目录会作为导航兜底：即使内存缓存清理掉了早期的目录分页，「上一章」「下一章」仍能正确解析。
- 阅读菜单提供「诊断」入口，可随时复制最近的读取链日志（含相邻章节解析结果），用于确认按钮不可用的真实原因。
- 所有读取用 WebView 只允许停留在被读取的站点内，章节页附带的弹窗广告跳转会被拦截，避免隐藏 WebView 被广告页劫持后读不到正文或目录。
- 阅读时点击屏幕中央整列呼出菜单栏，菜单提供上一章、目录、下一章、设置和诊断；「上一章」的可用性只看是否真的存在上一章，不等待该章缓存完成。
- 中央菜单的“上一章”从上一章开头打开；正文顶部的连续滚动和横向第一页左滑仍衔接到上一章末尾。
- 横向阅读的下一章与上一章同样按目录解析：目录里存在下一章时会把它的首段接在当前章之后连续翻页，第一页往右翻会回到上一章末页，不依赖章节页自带的链接。
- 上一章、目录、下一章只在中央菜单中提供，不在正文开头或末尾重复显示。
- 点击目录后从左侧打开竖排目录抽屉，仅在打开时定位并高亮当前章节一次；目录在后台追加新页时不会打断浏览。
- 目录抽屉只在打开时才抓取：打开时先取第一页，列表滚到底部再取下一批（一批 5 页），批次之间节流 1.2 秒；阅读正文时目录抓取完全停止，关闭抽屉立即停止，已抓到的进度和下一页地址会存本地，下次打开目录从断点继续。
- 目录抽屉追加新页时不会重置列表，也不会把镜头拉回当前阅读章节；只有重新打开抽屉时才定位到当前章节一次。目录顶部提供「跳到指定章」输入框：输入章节序号后点「跳转」即可直接打开该章（目录标签带章节号时按编号匹配，没有编号时按条目序号）。
- 设置面板支持翻页方式、屏幕方向、字号、行距、象牙白/纸张灰/夜间墨色；屏幕方向默认锁定竖屏，也可主动切换横屏或跟随系统。
- 保存每个网页地址的阅读位置。
- 中央菜单提供上一章、目录、下一章操作，横向翻到正文末尾后自动续接下一章。
- 每次启动时自动检查 GitHub Releases（直连不可用时自动改用镜像接口），也可在首页点击“检查更新”；发现更高版本后提示下载 APK，下载链接同样会先探测可用的镜像。
- 从其他应用分享链接启动应用时会真正打开该网址，而不是停留在上次恢复的书上；分享链接每次启动只打开一次，返回书架后不会被重新拉回阅读页。
- 页面路由使用常量而不是枚举名字比较：之前主界面分支只匹配首页值，从阅读页返回书架时会落到阅读分支，看起来像「返回书架 / 返回没反应」。

## GitHub 发布与更新

应用通过 `app/src/main/java/com/example/jingdu/UpdateChecker.kt` 检查公开仓库 `https://github.com/superZZZ101/jingdu-reader-android` 的最新 Release。

发布版本时递增 `app/build.gradle.kts` 中的 `versionCode` 和 `versionName`，然后创建形如 `v1.4.0` 的 Git 标签并推送。`.github/workflows/release.yml` 会构建签名 APK 并发布到 GitHub Release，应用下次启动时会检测到它。签名密钥只通过 GitHub Actions Secrets 提供，不要提交 `keystore.properties` 或 `.jks` 文件。

## 打开方式

用 Android Studio 打开本目录，等待 Gradle 同步后运行 `app` 模块。Debug APK 默认输出到 `app/build/outputs/apk/debug/app-debug.apk`。

提交前可运行 `node tools/check-reader-script.mjs` 校验 `ReaderScript` 里的注入脚本语法；该脚本以字符串形式保存，语法错误只会表现为所有站点静默读取失败，所以修改解析规则后应先跑这一步。

`tools/device-check.ps1` 和 `tools/device-tap.ps1` 用于真机/模拟器回归：前者用 SEND intent 打开网址并输出应用真实写入的正文、目录和导航状态，后者按屏幕文本点击按钮。

`app/src/androidTest/java/com/example/jingdu/CatalogDrawerTest.kt` 覆盖目录抽屉的两条关键行为：滚到底部请求下一批、追加新页不重置列表、只有重新打开抽屉才定位当前章节。用 `gradlew :app:connectedDebugAndroidTest` 在连接的设备上运行。

`tools/fixture-book-server.js` 提供一个本地测试书站（12 页目录、每页 20 章、正文分两页），当真实站点不可用时可用它回归目录抓取链路：

```powershell
node tools/fixture-book-server.js 8765                       # 宿主机启动
adb shell am start -a android.intent.action.SEND -t text/plain `
  --es android.intent.extra.TEXT "http://10.0.2.2:8765/book/3.html" `
  -n com.example.jingdu/.MainActivity                        # 模拟器用 10.0.2.2 访问宿主机
```

应用需要网络权限以加载用户输入的网页；页面正文只在设备本地提取和渲染，不上传到第三方服务。它不绕过登录、付费限制或 DRM。
