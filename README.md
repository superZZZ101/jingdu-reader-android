# 静读 Android App

手机端 Android 版本的静读阅读模式。应用使用 WebView 在本地加载网页，再通过页面内 JavaScript 提取正文、目录章节链接和目录分页，阅读内容由原生 Compose 界面渲染。

## 功能

- 输入小说网页地址并打开。
- 首页提供本地书架，支持查看、继续阅读和移除书籍。
- 阅读页中央菜单支持将当前书籍加入书架，书架会记录最近阅读章节；移除书籍只在书架页操作。
- 自动识别正文和目录页。
- 目录页完整渲染章节链接，不限制 500 章。
- 识别 `上一页`、`下一页`、`101-200`、`第 2 页` 等目录分页链接，并在后台自动加载、合并所有可发现的目录页。
- 手机端支持上下滚动和左右分页两种翻页方式，并记住选择。
- 阅读窗口固定保持当前章、上一章和下一章三章数据：当前章由活动 WebView 读取，前后章由两路独立 WebView 并行预加载，解析后存入本地内存缓存；阅读切章命中缓存时直接衔接。
- 上下阅读会把已缓存的上一章、本章和下一章接在同一条滚动内容中，向上或向下滚入相邻章节时连续衔接；停在章节首尾不会自动跳转，只有继续滚动或边界手势才会进入相邻章节。
- 从章节开头左翻会落到上一章末页，从章节末尾右翻会落到下一章首屏。
- 上下/左右阅读模式切换时会保留当前正文偏移，不再因残留的章节起始定位标记跳回本章开头。
- 横向模式下系统状态栏和导航栏背景会跟随当前象牙白、纸张灰或夜间墨色设置，正文与页码仍限制在安全区域内。
- 阅读页中央五分之一宽度区域用于呼出菜单，左右区域用于翻页；横向模式支持点击左侧上一页、右侧下一页，或通过短滑动立即翻页；设置中可改为左右两侧都进入下一页。
- 横向阅读在第一页右滑可回到上一章末页，末页左滑可进入下一章首屏。
- 对分成多个网页的章节自动合并 `上一页`/`下一页` 正文，章节标题去除分页和站点后缀；纵向和横向阅读都显示完整标题，横向首页会按标题实际高度重新分页；分页截点落在完整视觉行末，正文底部保留 1dp 安全间距；只有靠近页面边界的段落换行才会优先保留，较长段落会在页面中连续分页，避免前页留下大段空白；末尾连续的短页、孤立标点或引号会合并后重新平衡，必要时减少页数，避免生成异常留白页。
- 分页链或下一章缓存尚未完整时不会提前提交章节切换，待正文合并完成后再继续阅读。
- 阅读器会过滤正文中的导航、强制阅读提示和浏览器错误页；前后章预读取和原生 HTML 兜底会沿用当前 WebView 的站点 Cookie 与 Referer，遇到普通预读取失败时自动转到活动 WebView 继续加载；遇到 Cloudflare 安全验证时保留可交互的 WebView，验证通过后继续提取章节。
- 网页读取失败时错误页会保留最近 80 条诊断事件，可一键复制或通过 Android 分享面板发送；日志包含应用版本、设备 API、加载阶段、网页地址、请求 token、WebView/HTTP 错误和重试状态，不包含正文内容。
- 当前章节正文和阅读位置会在切换页面、离开阅读页及进程结束前保存，重新打开书架或最近阅读可继续原位置；已合并的目录独立保存，应用重启后可继续目录加载。
- 恢复已保存的章节时会立即重新准备前后章节缓存，避免首次读到章节边界时退回活动网页加载。
- 阅读时点击屏幕中央整列呼出菜单栏，菜单提供上一章、目录、下一章和设置。
- 中央菜单的“上一章”从上一章开头打开；正文顶部的连续滚动和横向第一页左滑仍衔接到上一章末尾。
- 上一章、目录、下一章只在中央菜单中提供，不在正文开头或末尾重复显示。
- 点击目录后从左侧打开竖排目录抽屉，仅在打开时定位并高亮当前章节一次；目录在后台追加新页时不会打断浏览。
- 打开目录抽屉时独立加载目录；分页会自动合并，正常完成后无需手动翻页，失败时可重试。
- 设置面板支持翻页方式、屏幕方向、字号、行距、象牙白/纸张灰/夜间墨色；屏幕方向默认锁定竖屏，也可主动切换横屏或跟随系统。
- 保存每个网页地址的阅读位置。
- 中央菜单提供上一章、目录、下一章操作，横向翻到正文末尾后自动续接下一章。
- 每次启动时自动检查 GitHub Releases，也可在首页点击“检查更新”；发现更高版本后提示下载 APK。

## GitHub 发布与更新

应用通过 `app/src/main/java/com/example/jingdu/UpdateChecker.kt` 检查公开仓库 `https://github.com/superZZZ101/jingdu-reader-android` 的最新 Release。

发布版本时递增 `app/build.gradle.kts` 中的 `versionCode` 和 `versionName`，然后创建形如 `v1.4.0` 的 Git 标签并推送。`.github/workflows/release.yml` 会构建签名 APK 并发布到 GitHub Release，应用下次启动时会检测到它。签名密钥只通过 GitHub Actions Secrets 提供，不要提交 `keystore.properties` 或 `.jks` 文件。

## 打开方式

用 Android Studio 打开本目录，等待 Gradle 同步后运行 `app` 模块。Debug APK 默认输出到 `app/build/outputs/apk/debug/app-debug.apk`。

应用需要网络权限以加载用户输入的网页；页面正文只在设备本地提取和渲染，不上传到第三方服务。它不绕过登录、付费限制或 DRM。
